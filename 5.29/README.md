# Aero-Twin 5.11test

基于 RK3588 的自动驾驶视觉主程序。当前版本的目标不是“离线最准确”，而是“在板端实时稳定地完成赛道跟踪、目标检测、路牌识别和速度约束”。

这套系统的核心思路是：

- `Seg` 负责主控闭环，优先保证路径跟踪稳定
- `YOLO` 负责目标检测，尽量实时输出环境目标和路牌框
- `OCR` 不做整帧文字检测，只对已经检测到的 `sign / limit_sign` ROI 做识别
- 线程之间优先保“最新帧”和“低延迟”，允许主动丢掉旧帧

## 项目结构

```text
.
├── config.py              # 所有核心参数与详细调参说明
├── main.py                # 主入口，线程调度、共享内存拉流、串口控制、网页推流
├── models/
│   ├── det/               # 检测模型
│   ├── ocr/               # OCR 识别模型和字典
│   └── seg/               # 分割模型
├── modules/
│   ├── detector.py        # PP-YOLOE RKNN 推理与后处理
│   ├── ocr_system.py      # OCR 识别封装，支持受限字符集解码
│   └── segmentor.py       # 分割、路径搜索、逆透视与控制量计算
└── utils/                 # 工具函数
```

## 当前实现逻辑

### 1. 图像输入与线程拆分

1. 上游采集进程把最新图像写入共享内存 `shm_ar_video`
2. `ai_producer_thread()` 从共享内存读取帧头里的 `frame_id / width / height`
3. 如果 `frame_id` 没变，说明还是旧帧，就继续等待
4. 来了新帧后，主线程把图像拆成两条分支
5. `seg_queue`
   输入 `320x320 RGB` 小图，给分割和路径规划用
6. `yolo_queue`
   输入 `YOLO_SIZE` 小图给检测，同时保留一份原分辨率 BGR 图给 OCR 裁图

预期效果：

- 下游处理不过来时，系统优先保“最新信息”，而不是死等旧帧算完
- 分割链路和检测链路互不阻塞，控制响应更稳

### 2. NPU 核分配

当前默认配置：

- `Seg -> Core 0`
- `OCR -> Core 1`
- `YOLO -> Core 2`

这样做的目的：

- 分割链路是主控闭环，必须稳定，所以单独占核
- YOLO 不再被 OCR 串行拖慢
- OCR 只在牌子出现时跑，但跑起来可能比预期更耗时，所以单独隔离

预期效果：

- YOLO 帧率更稳定
- OCR 不会把检测链路卡住
- 分割控制更少出现“因为识别慢导致的迟滞”

### 3. YOLO 检测逻辑

`yolo_worker()` 只做两件事：

1. 调用 `modules/detector.py` 执行检测
2. 把 `sign / limit_sign` 的 ROI 任务异步投给 OCR 线程

检测输出统一格式：

```python
{
    "rect": [x, y, w, h],
    "class_id": int,
    "class_name": str,
    "score": float,
}
```

后处理特点：

- 支持 PP-YOLOE 多分支输出
- 也兼容单 tensor 输出格式
- 会做按类别 NMS
- 会过滤一些明显异常的大框、贴边大框误检

预期效果：

- 页面上能稳定看到统一风格的检测框
- 一些大面积离谱误检不会直接流进后续控制链路

### 4. OCR 识别逻辑

当前 OCR 只做“识别”，不做整帧文字检测。

它的输入来自 YOLO 已经裁定好的 `sign / limit_sign` 框：

1. YOLO 先给出牌子框
2. 只有 ROI 尺寸超过阈值，才允许进入 OCR
3. OCR 从原分辨率图像上裁图，不从 `TARGET_RES` 显示图上裁图
4. 小 ROI 会先做一次温和放大，再送识别模型

#### `sign` 语义路牌

- 走普通识别解码
- 当前主要识别 `LEFT / RIGHT`
- 识别结果会更新 `turn_intent`

预期效果：

- 在分叉路口场景下，路径搜索可以利用语义牌给出左/右偏向
- 对太远、太小、字不完整的语义牌，系统宁可不识别，也尽量少误判

#### `limit_sign` 限速牌

- 进入 OCR 前同样要过 ROI 尺寸门槛
- OCR 解码时只允许数字字符 `0-9` 参与竞争
- 不是识别一次就生效，而是“连续识别到同一个数字 N 次”才生效
- 新牌子结果会覆盖旧牌子结果，覆盖依据是 `frame_id`

预期效果：

- 减少远距离小牌子、字符缺失、单帧抖动带来的误限速
- 避免旧牌子 OCR 迟到后把新牌子状态覆盖回去

### 5. 分割与路径规划逻辑

`modules/segmentor.py` 是当前主控核心。

它的流程是：

1. 对 `320x320 RGB` 图执行分割
2. 整理出赛道二值 `mask`
3. 从下往上逐层扫描 `mask`
4. 找每层的白色连通段中心
5. 把相邻层能接上的中心点连成多条候选路径
6. 对候选路径按长度、平滑度、横向漂移打分
7. 如果检测到 `stone`
   先判断石头更靠左支还是右支
   优先选“没有石头”的那一支
8. 如果没有明确石头干预
   默认优先走左侧分支
9. 如果此时有 `turn_intent`
   再用语义牌给出的左/右意图去覆盖默认偏向
10. 选出最终路径后，用多项式拟合成连续曲线
11. 把曲线逆透视到鸟瞰图，计算控制量

输出三样东西：

- `err_x`
  横向偏差，单位接近厘米
- `l_k`
  预瞄斜率，反映前方路径方向变化
- `rendered_img`
  调试预览图

预期效果：

- 车辆在正常赛道上能持续回中
- 没有额外干预时，岔路默认优先走左边
- 如果检测到石头，优先走没有石头的那一支
- 没有石头干预时，再结合语义牌偏向左/右通路
- 鸟瞰图里的控制量通常比直接在前视图上算更稳定

### 6. 控速逻辑

`serial_control_thread()` 里，目标速度不是固定值，而是分两层限制：

1. 基础动态速度
   先根据弯道程度算一个速度
   弯越大，速度越低
   直道时，速度更高
2. 限速牌上限
   如果当前已经确认了 `limit_sign`
   最终速度不能超过 `识别数字 - 1`

另外还有一层“斑马线 + 红绿灯”的停车约束：

1. 如果检测到 `zebra_crossing`
   会把检测框底边视作“停止线”
2. 页面上会把这条停止线画出来，并按一定比例向左右延长
3. 如果同时检测到 `traffic_light_red` 或 `traffic_light_yellow`
4. 并且停止线距离画面底部已经足够近
5. 则强制把线速度置为 `0`
6. 一旦检测到 `traffic_light_green`
   就解除这个停车状态，恢复原本的动态速度和限速牌逻辑

最终控制规则是：

```text
final_speed = min(弯道动态速度, 限速牌上限)
if 红灯/黄灯停车条件满足:
    final_speed = 0
```

预期效果：

- 直道尽量快
- 弯道自动更慢
- 限速牌只作为“天花板”，不会破坏弯道减速逻辑
- 车辆接近斑马线停止线且遇到黄灯/红灯时会停车
- 绿灯后会恢复原本的速度控制逻辑

### 7. 新牌子覆盖旧牌子

系统现在对 `turn_intent` 和 `speed_limit` 都带了帧号管理：

- YOLO 每一帧都有 `frame_id`
- OCR 任务会把这个 `frame_id` 一起带下去
- 回写结果时，只有更新帧或同帧结果才允许覆盖旧状态

预期效果：

- 旧 OCR 结果即使晚到，也不容易把新状态覆盖回去
- 页面上显示的 OCR 文字和当前检测框更一致

### 8. 页面预览逻辑

Flask 会把 `global_preview_frame` 编成 MJPEG 持续推流。
预览图里会叠加：

- 分割区域
- 规划线
- 鸟瞰图小窗
- YOLO 检测框
- 斑马线停止线
- OCR 识别文字
- Seg / YOLO FPS
- 当前目标速度
- 当前限速值
- 当前灯色
- 是否处于红黄灯停车状态

预期效果：

- 调试时可以快速判断是“模型没跑”还是“控制参数不对”
- 能直接观察 OCR 是否稳定、限速是否已经生效

## 当前使用的模型

默认配置见 [config.py](./config.py)：

- 分割模型：`models/seg/ppliteseg_320_320_int8.rknn`
- 检测模型：`models/det/detv2/ppyoloe_crn_m_80e_custom_raw_rk3588_fp16.rknn`
- OCR 模型：`models/ocr/ppocrv4_rec_fp16.rknn`

如果切换模型，最少要同步检查：

1. `YOLO_MODEL / SEG_MODEL / REC_MODEL_PATH`
2. `YOLO_SIZE / SEG_SIZE / REC_HEIGHT / REC_WIDTH`
3. `CLASS_NAMES`
4. `modules/detector.py` 的输出解析逻辑
5. OCR 字典 `DICT_PATH`

## 常用调参入口

### 1. OCR 识别稳定性

重点看这些配置：

- `OCR_MIN_SIGN_BOX_W / H`
- `OCR_MIN_LIMIT_SIGN_BOX_W / H`
- `OCR_CROP_EXPAND_RATIO`
- `OCR_MIN_CROP_HEIGHT`
- `LIMIT_SIGN_CONFIRM_FRAMES`

调参原则：

- 如果远距离误判很多
  优先增大最小 ROI 门槛
- 如果经常框到了但字缺边
  适当增大 `OCR_CROP_EXPAND_RATIO`
- 如果限速牌偶发抖动就生效
  增大 `LIMIT_SIGN_CONFIRM_FRAMES`

### 2. 检测性能与小目标能力

- `YOLO_SIZE`
- `JPEG_QUALITY`
- `CLASS_MIN_SCORES`

调参原则：

- 远处小牌子看不清时，可能要增大 `YOLO_SIZE`
- 页面卡顿但底层没问题时，优先先降 `JPEG_QUALITY`

### 3. 分割与车控

- `SRC_PTS`
- `DST_PTS`
- `CM_PER_PIXEL_X`
- `KP`
- `KD`
- `SERVO_CENTER`

调参原则：

- 线看着正常但控制发飘，先看逆透视标定
- 回中太慢调 `KP`
- 过弯过冲或跟弯迟钝调 `KD`

## 预期整体效果

在当前实现下，系统预期达到这些行为：

- 正常赛道上保持稳定循迹
- 分叉路口默认优先选左边
- 如果某一侧检测到石头，优先绕开石头所在分支
- 没有石头干预时，再根据 `LEFT / RIGHT` 牌子偏向对应车道
- 限速牌不会单帧乱跳立刻生效，而是稳定确认后才限速
- 新牌子状态会覆盖旧牌子状态
- 接近斑马线停止线时，红灯/黄灯会触发停车
- 检测到绿灯后，系统恢复到原本的动态速度与限速逻辑
- 弯道仍然更慢，直道仍然更快，只是整体不超过限速牌上限
- 太远太小、字不完整的路牌尽量不做 OCR，减少误判

## 备注

这份 README 按当前代码状态编写，当前事实是：

- `YOLO` 与 `OCR` 已拆线程
- `OCR` 独占 `Core 1`
- `YOLO` 独占 `Core 2`
- `Seg` 独占 `Core 0`

- 限速牌使用“数字受限解码 + 连续 N 次确认 + 新牌子覆盖旧牌子”
